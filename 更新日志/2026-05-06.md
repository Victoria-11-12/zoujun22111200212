## 技术亮点

### 1. LLM 应用的非确定性测试方案

**挑战**：LLM 输出具有随机性，传统精确断言无法适用，测试容易 flaky。

**解决方案**：
- **分层断言策略**：单元测试精确断言，集成测试采用宽松断言
- **关键字匹配**：意图分类链断言 `"NEED_SQL" in result`，不依赖具体表述
- **非空检查**：生成类链断言 `len(result.strip()) > 0`，验证有输出即可
- **结构化字段检查**：评估链使用 Pydantic 结构化输出，断言 `1 <= result.score <= 5`
- **SSE 格式检查**：流式响应断言 `"[DONE]" in chunks`，验证协议正确性

**效果**：集成测试偶发因 LLM 输出格式波动失败，重跑即可恢复，不影响 CI 稳定性。

### 2. Docker 沙箱测试环境配置

**挑战**：图表生成功能依赖 Docker 沙箱执行 Python 代码，测试环境搭建复杂。

**解决方案**：
- **环境隔离**：使用独立测试数据库 `movie_test`（端口 3307），与生产库完全隔离
- **三角色权限设计**：
  - `root`：管理员操作（批量增删改、回滚）
  - `readonly_user`：用户查询（只读权限）
  - `analyst`：评估系统（读写 eval_results 表）
- **Docker 沙箱安全限制**：
  - 内存限制 256MB
  - 网络隔离（`network_disabled=True`）
  - 只读文件系统（`read_only=True`）
  - 静态代码安全扫描（禁止 `os`、`sys`、`subprocess` 等危险导入）
- **测试数据管理**：E2E 测试依赖已有数据，管理员批量操作后自动回滚恢复

**测试覆盖**：
- 图表生成成功（SQL 查询 → 代码生成 → 沙箱执行 → HTML 返回）
- 代码生成失败重试（Eval 节点反馈 → Python Agent 重新生成）
- 沙箱执行失败处理（Docker 异常捕获 → 错误信息返回）
- 危险代码拦截（静态扫描拦截 → 直接返回错误）

### 3. 异步流式 API 测试

**挑战**：FastAPI 的 SSE（Server-Sent Events）流式响应测试困难，需要验证实时推送的每一帧数据。

**解决方案**：
- 使用 `httpx.AsyncClient` 建立异步 HTTP 连接
- `async with async_client.stream("POST", url, json=payload) as response` 捕获流式响应
- `async for line in response.aiter_lines()` 逐行读取 SSE 数据帧
- 断言每帧格式符合 SSE 规范（`data:` 前缀、JSON 格式）
- 验证流式结束标记 `[DONE]` 必达

**覆盖场景**：
- 正常对话流式返回
- SQL 查询结果流式包装
- 数据库无结果时浏览器搜索回退
- 安全威胁实时拦截
- 多轮对话上下文保持

### 4. 高覆盖率达成方法

**当前覆盖率**：85%（886 条语句，覆盖 754 条）

**达成策略**：
- **单元测试兜底**：纯函数、模型验证、工具安全检测等无需外部依赖的模块 100% 覆盖
- **集成测试补位**：Chains、Agents、Workflows 等依赖 LLM 的模块通过宽松断言覆盖核心路径
- **E2E 测试验证主链路**：4 个 API 路由的 20 个场景覆盖用户核心使用路径

**豁免模块**（技术原因允许低覆盖）：
- `web_tools.py`（8%）：调用外部命令行工具，单元测试需 Mock subprocess，实际风险低
- `analyst_service.py`（48%）：大量数据库查询和异步编排逻辑，集成测试已覆盖核心路径

## 测试质量保障

### 质量门禁

| 检查项 | 标准 | 阻断级别 |
|--------|------|---------|
| 单元测试通过率 | 100% | 阻断 |
| 集成测试通过率 | ≥ 95%（允许 LLM 偶发不稳定） | 警告 |
| E2E 测试通过率 | 100% | 阻断 |
| 代码覆盖率 | ≥ 80% | 警告 |
| 新增代码覆盖率 | ≥ 90% | 阻断 |

### 测试可靠性措施

- **并发控制**：评估测试使用 `Semaphore(5)` 限制并发数，防止数据库连接池耗尽
- **超时保护**：Docker 沙箱执行设置超时，防止死循环
- **自动回滚**：管理员批量操作测试后自动回滚，保证数据一致性
- **日志记录**：DEBUG 级别日志记录每个测试步骤，便于问题定位

## 工程化实践

### 自动化报告生成

- **HTML 测试报告**：pytest-html 生成自包含报告，含测试用例详情、耗时、失败截图
- **覆盖率报告**：pytest-cov 生成 HTML 覆盖率报告，支持文件级/函数级/类级钻取
- **测试日志**：DEBUG 级别日志记录 LLM 调用详情、数据库操作、Docker 执行

### 测试配置管理

- **环境隔离**：`.env.test` 文件配置测试专用环境变量，通过 `load_dotenv(override=True)` 覆盖
- **标记分层**：`@pytest.mark.unit`、`@pytest.mark.integration`、`@pytest.mark.e2e` 标记实现分层运行
- **异步支持**：`asyncio_mode = auto` 自动处理异步测试

### 运行命令

```bash
# 运行全部测试（生成报告 + 覆盖率）
pytest

# 按层级运行
pytest -m unit          # 仅单元测试，5 秒
pytest -m integration   # 仅集成测试，5 分钟
pytest -m e2e          # 仅 E2E 测试，3 分钟

# 按模块运行
pytest tests/unit/models/
pytest tests/integration/chains/
pytest tests/e2e/test_user_router.py
```

## 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| LLM 输出不稳定 | 集成测试偶发失败 | 宽松断言策略 + 重跑机制 |
| Docker 沙箱不可用 | 图表工作流测试全部失败 | 测试前检查 Docker Desktop 状态 |
| 数据库连接池耗尽 | 异步并发评估测试超时 | Semaphore(5) 限制并发数 |
| 测试数据库被污染 | E2E 测试结果不可信 | 管理员回滚测试自动恢复 |
