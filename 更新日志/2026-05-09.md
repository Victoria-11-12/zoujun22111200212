## 一、部署架构演进

### 1.1 三端微服务架构

| 服务 | 端口 | 职责 |
|------|------|------|
| Node.js（movie_web） | 3000 | 前端页面 + 基础 API |
| FastAPI（movie_fastapi） | 8000 | AI 对话、图表生成、质量评估 |
| Flask（movie_flask） | 5000 | 票房预测、黑马挖掘 |
| MySQL | 3306 | 数据存储 |

### 1.2 Nginx 反向代理统一入口

解决多端口暴露带来的安全风险和用户体验问题：

| 请求路径 | 转发目标 | 说明 |
|---------|---------|------|
| `/` | Node.js (3000) | 前端页面、静态资源 |
| `/api/flask/*` | Flask (5000) | 票房预测接口 |
| `/api/*` | FastAPI (8000) | AI 对话、图表、评估接口 |

**关键配置**：
- SSE 流式响应需关闭 Nginx 缓冲（`proxy_buffering off;`）
- `/api/flask/` 放在 `/api/` 之前，Nginx 按最长匹配优先
- 移除三个后端服务的端口暴露，仅暴露 Nginx 80 端口
- 本地开发模式不受影响，通过 `NGINX_MODE` 环境变量控制

## 二、核心技术问题解决

### 2.1 Git LFS 模型文件加载

**问题**：Flask 容器启动后 `joblib.load()` 抛出 `KeyError: 118`，模型加载失败

**原因**：`.pkl` 模型文件使用 Git LFS 管理，Docker 构建时只下载了 LFS 指针文件（几百字节），而非实际二进制文件（3.2 MB / 278 KB）

**解决方案**：在 `Dockerfile.flask` 中集成 Git LFS 拉取流程

```
安装 git-lfs → COPY .git 仓库元数据 → git lfs pull 拉取真实文件 → rm -rf .git 清理
```

### 2.2 CORS 跨域配置修复

**问题**：`allow_origins=["*"]` 与 `allow_credentials=True` 不能同时使用（CORS 规范限制），浏览器拦截响应

**解决方案**：显式配置允许的源地址列表，从硬编码改为环境变量读取

```python
FRONTEND_URL = os.getenv('FRONTEND_URL', 'http://localhost:3000')
allow_origins=[FRONTEND_URL]
```

### 2.3 Docker 连接协议跨平台兼容

**问题**：Linux 服务器上报错 `The npipe:// protocol is only supported on Windows`

**原因**：代码中强制设置了 Windows 命名管道协议 `npipe:////./pipe/docker_engine`

**解决方案**：添加操作系统判断，仅 Windows 下设置命名管道

```python
if sys.platform == 'win32':
    os.environ['DOCKER_HOST'] = 'npipe:////./pipe/docker_engine'
```

### 2.4 静态文件中间件拦截动态路由

**问题**：前端无法加载动态生成的 `config.js`，浏览器报错 404

**原因**：`express.static('./')` 在自定义路由之前处理请求

**解决方案**：将动态配置路由移到静态文件中间件之前

```javascript
// 先处理动态路由
app.get('/js/config.js', ...);
// 再处理静态文件
app.use(express.static('./'));
```

### 2.5 Docker 部署环境变量注入

**问题**：前端 JS 使用 `localhost` 连接后端，浏览器无法访问容器内的 localhost

**解决方案**：在 `docker-compose.yml` 中为各服务注入环境变量，Node.js 动态生成 `config.js` 注入前端配置

**实现机制**：
- 后端：`os.getenv('FRONTEND_URL', 'http://localhost:3000')` 读取环境变量
- 前端：`window.__CONFIG__.FASTAPI_URL` 获取动态配置
- Nginx 模式：注入空字符串，前端使用相对路径 `/api/...`

## 三、数据库权限设计

### 3.1 用户角色分离

| 用户 | 权限 | 用途 |
|------|------|------|
| `readonly_user` | 仅 `movies` 表 SELECT | 普通用户查询电影数据 |
| `analyst` | 多表 SELECT + `eval_results` INSERT | 评估模块查询日志和写入评估结果 |

### 3.2 自动初始化机制

通过 MySQL 容器 `docker-entrypoint-initdb.d` 目录实现自动化：

```
volumes:
  - ../movie_db.sql:/docker-entrypoint-initdb.d/01-init.sql:ro
  - ../init-users.sql:/docker-entrypoint-initdb.d/02-init-users.sql:ro
```

- `01-init.sql`：创建表结构和初始数据
- `02-init-users.sql`：创建权限用户

### 3.3 问题修复

**Access denied for user 'analyst'**：`docker-compose.yml` 中 `MYSQL_USER` 环境变量只能创建一个用户，无法满足多用户需求。创建独立 `init-users.sql` 脚本，在容器首次启动时自动执行。

### 部署流程

```bash
# 1. 配置环境变量
cp 配置文档/.env.example 配置文档/deployment/.env
# 编辑 .env 填入实际地址和 API_KEY

# 2. 构建沙箱镜像
docker build -t pyecharts-sandbox ../../fastapi

# 3. 启动所有服务
cd 配置文档/deployment
docker compose up -d

# 4. 验证状态
docker compose ps
```

## 七、技术要点总结

1. **Git LFS 集成**：Docker 构建大文件需要特殊处理，不能直接 COPY
2. **CORS 安全规范**：通配符 `*` 与凭证不能共存，需显式配置源地址
3. **跨平台兼容**：Windows 命名管道与 Unix Socket 需条件判断
4. **环境变量分层**：本地开发默认值 + 生产环境 `.env` 覆盖
5. **Nginx SSE 支持**：流式响应必须关闭代理缓冲
6. **动态配置注入**：Node.js 动态生成 config.js，前端统一读取配置
7. **数据库权限分离**：多用户角色（readonly_user / analyst），最小权限原则
