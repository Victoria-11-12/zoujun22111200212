# 2026-05-20

## 概述

完成 Prometheus + Grafana 监控体系的完整搭建，实现 Nginx、Node.js、Flask、FastAPI 四端服务的统一监控，新增 Agent Token 消耗追踪功能，提供一键启动脚本简化多服务启动流程。

---

## 一、Prometheus 监控体系搭建

### 1.1 监控架构

| 组件 | 端口 | 职责 |
|------|------|------|
| Nginx Exporter | 9113 | Nginx 状态指标采集 |
| Prometheus | 9090 | 指标存储与查询 |
| Grafana | 3001 | 可视化面板 |

### 1.2 Nginx 监控配置

修改 `nginx.local.conf`，添加状态监控端点：

```nginx
location /nginx_status {
    stub_status on;
    access_log off;
    allow 127.0.0.1;
    deny all;
}
```

### 1.3 Prometheus 采集配置

配置四个监控任务：

| 任务 | 目标 | 标签 |
|------|------|------|
| nginx | localhost:9113 | app: nginx |
| nodejs | localhost:3000 | app: nodejs |
| flask | localhost:5000 | app: flask |
| fastapi | localhost:8000 | app: fastapi |

## 六、Grafana 面板配置

### 6.1 HTTP 监控面板

| 面板 | 查询语句 | 用途 |
|------|---------|------|
| 请求数 | `http_requests_total{service=~"nodejs\|flask\|fastapi", endpoint!~"/metrics\|metrics"}` | 各服务端点请求量趋势 |
| 平均延迟 | `rate(http_request_duration_seconds_sum[5m]) / rate(http_request_duration_seconds_count[5m])` | 服务响应延迟 |
| QPS | `rate(http_requests_total[1m])` | 每秒请求数 |
| 登录统计 | `auth_requests_total` | 登录成功/失败次数 |

### 6.2 Token 消耗面板

| 面板 | 查询语句 | 用途 |
|------|---------|------|
| Input Token | `agent_token_usage_total{token_type="input"}` | 各 Agent 输入 Token 消耗 |
| Output Token | `agent_token_usage_total{token_type="output"}` | 各 Agent 输出 Token 消耗 |
| 总消耗 | `sum(agent_token_usage_total) by (agent)` | 按 Agent 汇总 |
| 全局总计 | `sum(agent_token_usage_total)` | 全部 Agent 总消耗 |

## 七、问题解决记录

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| Grafana 启动闪退 | 缺少 homepath 参数 | 添加 `-homepath .` 参数 |
| Flask /metrics 404 | prometheus_flask_exporter 在 debug=True 时子进程重载导致端点丢失 | 改用 prometheus_client 手动实现 |
| Grafana 查询语法错误 | 标签值未用引号包裹 | 使用正确语法 `{service="nodejs"}` |
| Node.js prom-client 未找到 | 未安装依赖 | 执行 `npm install prom-client` |
| 管理员界面 404 | 直接访问 localhost:3000 未走 Nginx 代理 | 通过 http://localhost/admin.html 访问 |
